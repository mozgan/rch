# DBMS benchmark evidence

PostgreSQL/PostGIS point tables use input, Hilbert and RCH COPY insertion orders. Each has a forced sequential-scan arm and a 3D ND GiST candidate-filter arm with exact inclusive XYZ recheck. Indexed arms allow planner-selected sequential scans, reported in plan_metrics.csv. Client wall includes SQL planning/execution, ID sorting/transport/decoding/materialization; hashing/oracle are outside. Server execution and buffer counters come from separate EXPLAIN ANALYZE diagnostic passes. Shared buffer reads are not physical device I/O. Workload warmup does not guarantee all data resides in cache. Load/index/vacuum times exclude prior SFC ordering. No total preparation break-even, server RSS, cold-cache, general DBMS superiority or HistSFC/SplitSFC/pgPointCloud replication is claimed. Bootstrap intervals are within each fixed dataset, not independent-scene inference.
