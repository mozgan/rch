# compact_hilbert_vectors.jsonl Provenance

Status: definition-pinned in-repository oracle, not an external third-party oracle.

The vectors in `compact_hilbert_vectors.jsonl` are checked by the compact-Hilbert
definition used in the paper and implementation:

1. choose the compact domain from `bits_axis`;
2. embed each valid compact-domain point in the padded standard 3D Hilbert grid at
   `max(bits_axis)`;
3. rank valid compact-domain points by their padded standard Hilbert key;
4. use that rank as `rank_by_definition` and the expected compact key.

Machine-verification command:

```text
cmake --build build/debug --target test_compact_hilbert_oracle -j 4
./build/debug/tests/oracle/test_compact_hilbert_oracle
```

The oracle test recomputes `rank_by_definition` by exhaustive padded-standard
ordering over the compact domain, checks `compact == rank_by_definition`, checks
`Hilbert3Compact::encode`, and round-trips `Hilbert3Compact::decode`.

Limitation: this is a definition-pinned regression/provenance check. It is not
claimed to be independently generated by a third-party implementation.
